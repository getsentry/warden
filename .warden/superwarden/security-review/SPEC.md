# security-review Superwarden Specification

## Intent

This is a Superwarden skill. It is the broad security-review parent for Warden's TypeScript codebase.

The initial prompt lives in `warden.yaml.initialPrompt`. It is the source prompt for synthesis, not a regeneration transcript. The parent plan decomposes that prompt into focused child skills that run through normal Warden task execution.

## Scope

In scope:

- Vulnerabilities in changed TypeScript code under Warden's runtime, CLI, GitHub Action, config loading, skill loading, SDK execution, output rendering, or filesystem behavior.
- Authorization and trust-boundary failures.
- Secret, token, credential, and environment variable exposure.
- Unsafe filesystem access, path traversal, symlink handling, cache poisoning, and unintended writes.
- Command execution, shell argument handling, process spawning, and tool permission boundaries.
- Remote skill loading and untrusted repository input.
- GitHub event, pull request, and workflow data handling.
- Prompt-injection paths that can alter Warden behavior or leak sensitive context.

Out of scope:

- Generic code style.
- Speculative hardening with no triggerable attack path.
- Dependency freshness reports without a changed-code exploit path.
- Issues that require unrealistic control of a trusted local developer machine.
- Installing generated child skills into `.agents/skills/`.
- Replacing Warden's normal finding schema with a custom child skill output schema.

## Users And Trigger Context

- Primary users: Warden maintainers synthesizing or running a broad security review through focused Superwarden tasks.
- Common user requests: synthesize security-review, regenerate task skills, inspect the Superwarden plan, or run security-review against changed files.
- Should not trigger for: non-security code review, ordinary direct skills, or requests that only need one narrow preexisting skill.

## Runtime Contract

- The parent artifact lives in `.warden/superwarden/security-review/`.
- The config marker is currently `mode = "coordinator"`.
- Synthesis writes the Superwarden plan and synthesis metadata into the parent cache JSON.
- Synthesis writes focused child skills under the plan-specific cache directory.
- Each child skill cache entry includes only `SKILL.md`, `SPEC.md`, and `SOURCES.md`.
- Child skills are runnable by path and must not be installed into `.agents/skills/`.
- Parent synthesis must act as a deep planning pass, not a shallow category split.
- Each child skill must be generated by its own deep synthesis run, not by templating the parent plan task.
- Parent cache metadata must preserve child generation duration, token usage, cost, artifact size, source count, response model, turn count, and task/source hashes.
- Synthesis must identify missing repository, technology, deployment, or threat-model context inside generated tasks when live inquiry is not available.
- Child skills must require repo-local source inspection, relevant public prior art, and concrete changed-line evidence.
- Child skills must prohibit sending repository code, secrets, private file paths, or proprietary details to web tools.

## Source And Evidence Model

Authoritative sources:

- `warden.yaml` for the initial prompt, source files, output contract, and Superwarden metadata.
- `SKILL.md` for the parent runtime prompt.
- `SPEC.md` for the parent maintenance contract.
- `SOURCES.md` for source provenance, decisions, coverage, gaps, and changelog.

Useful improvement sources:

- Generated parent plan cache records and child skill metadata.
- Warden CLI output and JSONL logs from Superwarden synthesis and task execution.
- User feedback about missing task coverage, duplicate reports, false positives, or weak child skill instructions.
- Public security guidance and vulnerability prior art used during parent or child synthesis.

Data that must not be stored:

- Secrets, credentials, customer data, private URLs, or proprietary source excerpts that are not needed for reproducible synthesis.

## Reference Architecture

- `SKILL.md` contains the concise parent runtime prompt.
- `warden.yaml` contains the initial prompt and generated artifact contract.
- `SPEC.md` contains the maintenance contract for the parent Superwarden skill.
- `SOURCES.md` contains source provenance, decisions, coverage, gaps, and changelog.
- `cache/<plan-hash>.json` contains the validated plan and child synthesis metadata.
- `cache/<plan-hash>/skills/<task-id>/` contains runnable child skill artifacts.

## Evaluation

- Lightweight validation: run `warden synth security-review --show-plan` and inspect task coverage, missing inputs, and source provenance.
- Structural validation: run the skill-writer quick validator against this parent and generated child skill directories with strict depth enabled.
- Behavioral validation: run `warden <files> --skill security-review` and confirm Superwarden expands into child task executions with normal Warden findings.
- Acceptance gates: generated artifacts preserve the initial prompt, avoid duplicate task scopes, pass structural validation, and produce findings only with concrete changed-line evidence.

## Known Limitations

- Superwarden synthesis cannot ask live follow-up questions yet; missing context must be recorded in plan or child skill artifacts.
- Existing cached child skills may predate the current skill-writer structural requirements and should be regenerated when validation matters.
- Public prior-art research must use public names and concepts only, not repository source or secrets.

## Maintenance Notes

- Update `SKILL.md` when the parent runtime prompt or trigger behavior changes.
- Update `warden.yaml` when the initial prompt or generated artifact contract changes.
- Update `SOURCES.md` when source provenance, coverage, decisions, gaps, or synthesis rationale changes.
- Regenerate cached plans and child skills after changing parent intent, runtime contract, or source files.
